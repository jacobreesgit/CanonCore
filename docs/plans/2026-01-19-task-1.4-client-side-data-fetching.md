## Findings Summary

### Rule 1: client-swr-dedup

**No issues requiring SWR implementation.**

The codebase uses appropriate patterns for data fetching:

- `use-username-validation.ts` - Custom debouncing with abort controller for username checks
- `use-go-to-item.ts` - Server action calls (SWR not applicable)
- `spotlight-search.tsx` - Self-implemented module-level cache with SWR-like behavior

### Rule 2: client-event-listeners

**No issues found.**

All global event listeners are properly managed:

- `use-online-status.ts` - Online/offline events (rare, cheap)
- `spotlight-context.tsx` - Singleton provider pattern
- `use-mobile.ts` - matchMedia change events

### Rule 3: client-localstorage-schema

**3 files with issues - Missing try-catch around localStorage operations.**

localStorage operations can throw in:

- Safari/Firefox incognito/private browsing
- When storage quota is exceeded
- When localStorage is disabled

| File                               | Lines                  | Issue                                 |
| ---------------------------------- | ---------------------- | ------------------------------------- |
| `hooks/use-hero-collapse.ts`       | 27, 35                 | `getItem`/`setItem` without try-catch |
| `hooks/use-items-sort-filter.ts`   | 45-46, 52-53, 109, 117 | `getItem`/`setItem` without try-catch |
| `components/items/view-toggle.tsx` | 35, 48                 | `getItem`/`setItem` without try-catch |

**Note:** All three files use `useSyncExternalStore` which is the correct hydration-safe pattern. They also have validation logic. The only issue is missing try-catch.

### Rule 4: client-passive-event-listeners

**No issues found.**

No scroll, touch, or wheel event listeners were found in the audited files. The codebase uses:

- IntersectionObserver for lazy loading (proper)
- matchMedia for viewport detection (proper)
- keydown for keyboard shortcuts (not scroll-related)
- online/offline for connectivity (not scroll-related)
