## Detailed Findings

### Rule 1 & 3: URL State Management

**Status:** ⚠️ Architectural Gap (Deferred to Future Work)

**Current Implementation:**

Sort, filter, and view mode state are stored in localStorage:

```typescript
// hooks/use-items-sort-filter.ts:44-65
const SORT_STORAGE_KEY = "canoncore-items-sort";
const FILTER_STORAGE_KEY = "canoncore-items-filter";

function getSortSnapshot(): SortOption {
  const stored = localStorage.getItem(SORT_STORAGE_KEY);
  return stored && isValidSortOption(stored) ? stored : DEFAULT_SORT;
}
```

```typescript
// components/items/view-toggle.tsx:21,34-41
const STORAGE_KEY = "items-view-mode";

const getSnapshot = useCallback((): ViewMode => {
  const stored = localStorage.getItem(STORAGE_KEY);
  return stored === "tree" ? "tree" : "grid";
}, []);
```

**Benefits of Current Approach:**

1. **Cross-tab sync:** `useSyncExternalStore` with storage events enables sync across tabs
2. **Persistent preferences:** User's sort/filter/view preferences persist across sessions
3. **Fast transitions:** No URL updates = no navigation/re-render overhead
4. **Hydration-safe:** Server snapshots return defaults, client hydrates from localStorage

**Tradeoffs:**

1. **Not shareable:** Users cannot share links like `/my-items?sort=name-asc&filter=has-files`
2. **No deep-linking:** Bookmarks don't preserve specific views
3. **No browser history:** Back/forward doesn't restore previous sort/filter states

**Recommendation:** Add to Future Work. This is an intentional design decision with valid tradeoffs. The localStorage approach prioritizes persistent user preferences over shareability. A migration to URL-based state (using `nuqs` or `useSearchParams`) could be considered if sharing becomes a user need.

### Rule 2: Links Use `<a>`/`<Link>`

**Status:** ✅ Compliant

**Findings:**

1. **External links use `<a>`:**

   `item-context-menu.tsx:136-149`:

   ```tsx
   <ContextMenuItem asChild className="gap-2">
     <a
       href={`https://drive.google.com/drive/folders/${driveFileId}`}
       target="_blank"
       rel="noopener noreferrer"
     >
       <ExternalLink aria-hidden="true" className="size-4" strokeWidth={2} />
       <span>Open in Drive</span>
     </a>
   </ContextMenuItem>
   ```

2. **Programmatic navigation uses `router.push()`:**

   `items-view.tsx:276-281`:

   ```tsx
   const handleItemClick = useCallback(
     (id: UniqueIdentifier) => {
       router.push(`/my-items/${id}`);
     },
     [router]
   );
   ```

   This is appropriate for click handlers on interactive elements (grid items, tree nodes) where the entire element is clickable.

**No violations found.**

### Rule 4: Destructive Actions Need Confirmation

**Status:** ✅ Compliant

**Single Item Delete:**

`item-context-menu.tsx:169-196`:

```tsx
<Dialog open={deleteOpen} onOpenChange={setDeleteOpen}>
  <DialogContent className="sm:max-w-md">
    <DialogHeader>
      <DialogTitle>Delete Item</DialogTitle>
      <DialogDescription>
        Are you sure you want to delete &ldquo;{itemName}&rdquo;? This will also
        delete all child items. This action cannot be undone.
      </DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <Button variant="outline" onClick={() => setDeleteOpen(false)}>
        Cancel
      </Button>
      <Button variant="destructive" onClick={handleDelete}>
        {isLoading ? "Deleting..." : "Delete"}
      </Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

**Bulk Delete:**

`items-view.tsx:800-832`:

```tsx
<Dialog open={bulkDeleteDialogOpen} onOpenChange={setBulkDeleteDialogOpen}>
  <DialogContent className="sm:max-w-md">

      <DialogTitle>Delete Items</DialogTitle>

        Are you sure you want to delete {bulkSelection.selectionCount}{" "}

      </Button>

  </DialogContent>
</Dialog>
```
