## Overview

Audited all 60+ custom components in `components/` (excluding `ui/`) and all hooks in `hooks/` against the 7 re-render optimization rules from `skills/react-best-practices/rules/rerender-*.md`.

## Rules Checked

1. **rerender-defer-reads** - Don't subscribe to state only used in callbacks
2. **rerender-memo** - Extract expensive work into memoized components
3. **rerender-dependencies** - Use primitive dependencies in effects
4. **rerender-derived-state** - Subscribe to derived booleans, not raw values
5. **rerender-functional-setstate** - Use functional setState for stable callbacks
6. **rerender-lazy-state-init** - Pass function to useState for expensive values
7. **rerender-transitions** - Use startTransition for non-urgent updates

## Findings

### ✅ No Violations Found

The codebase demonstrates excellent adherence to React re-render optimization patterns. All 7 rules are followed correctly.

### Best Practices Already in Place

#### 1. rerender-defer-reads

- `components/google-drive/oauth-toast.tsx` uses `useSearchParams()` correctly - values are needed immediately in the useEffect for rendering logic (showing toasts, triggering sync)

#### 2. rerender-memo

- No instances where expensive inline computations could benefit from extraction to memoized components

#### 3. rerender-dependencies

- Effects use primitive dependencies where appropriate
- Object dependencies are used intentionally when object identity matters

#### 4. rerender-derived-state

- **Excellent example**: `hooks/use-items-sort-filter.ts` uses `useSyncExternalStore` for localStorage and derives booleans `isCustomSort` and `hasActiveFilter` with `useMemo`:
  ```typescript
  const isCustomSort = useMemo(() => sortBy === "custom", [sortBy]);
  const hasActiveFilter = useMemo(() => filterBy !== "all", [filterBy]);
  ```

## Conclusion

The CanonCore codebase exhibits strong React re-render optimization practices:

1. **Functional setState** is used consistently for toggle operations and Set mutations
2. **Lazy initialization** is applied where computations are expensive
3. **Derived state** is memoized with appropriate dependencies
4. **useTransition** is used for non-urgent background operations
5. **useSyncExternalStore** is used for hydration-safe localStorage access

No code changes were required. The existing patterns should be maintained as the codebase evolves.

## Recommendations

### For Future Development

1. Continue using functional setState for any toggle or array/Set mutation operations
2. Use `useSyncExternalStore` for localStorage/external state (as in `use-items-sort-filter.ts`)
3. Wrap non-urgent data fetches in `startTransition` (as in `items-view.tsx`)
4. Use lazy initialization `useState(() => ...)` only for expensive computations, not for simple props or primitives

### Patterns to Follow

```typescript
// ✅ Functional setState for toggles
setIsOpen((prev) => !prev);

// ✅ Functional setState for Set mutations
setSelectedIds((prev) => {
  const next = new Set(prev);
  if (next.has(id)) next.delete(id);
  else next.add(id);
  return next;
});

// ✅ Non-urgent updates with startTransition
startTransition(() => refetchItems());

// ✅ Derived state with useMemo
const isCustomSort = useMemo(() => sortBy === "custom", [sortBy]);
```
