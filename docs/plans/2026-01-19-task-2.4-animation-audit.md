# Task 2.4: Animation Audit

Audit of animation and transition patterns against web design guidelines.

**Rules checked:**

1. Honor `prefers-reduced-motion`
2. Animate only `transform`/`opacity`
3. Never use `transition: all`
4. Set correct `transform-origin`
5. SVG transforms on `<g>` wrapper
6. Animations must be interruptible

## Rule 2: Animate only transform/opacity

### Findings

**All compliant.** The codebase correctly animates only:

- `opacity` - fade-in/fade-out
- `transform` (translate3d, scale3d, rotate) - slide, zoom, spin
- `height` - Only in motion/react with spring animations (acceptable for smooth accordion/stepper UX)

The tw-animate-css library uses transform and opacity exclusively in its keyframes.

## Rule 6: Animations must be interruptible

### Findings

**All compliant.** Animation patterns used:

1. **motion/react spring animations** - Interruptible by design (spring physics allows interruption)
2. **dnd-kit animations** - Interruptible (drag operations can be cancelled)
3. **tw-animate-css** - CSS animations without `animation-fill-mode: forwards` lock
4. **Tailwind transitions** - CSS transitions are interruptible

## Implementation Notes

### Reduced Motion Global CSS

Added to `globals.css`:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

This provides a global fallback while individual components can still use `useReducedMotion` for more nuanced control.

### Shader1 Reduced Motion

When reduced motion is preferred, the shader displays a static gradient instead of the animated WebGL effect.

### ItemHero Reduced Motion

When reduced motion is preferred:

- Layout animations are disabled (`layout={!shouldReduceMotion}`)
- Spring transitions use instant duration
- Opacity transitions remain (non-distracting)
