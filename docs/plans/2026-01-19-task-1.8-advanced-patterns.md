## Rules Applied

### 1. `advanced-event-handler-refs`

**Purpose:** Store event handlers in refs when used in effects that shouldn't re-subscribe on callback changes.

**Pattern to detect:** Hooks that accept callback props and use them inside `addEventListener`/`useEffect` subscriptions without storing in refs.

### 2. `advanced-use-latest`

**Purpose:** Use `useLatest` hook to access latest values in callbacks without adding them to dependency arrays.

**Pattern to detect:** Effects that include callback props in dependency arrays, causing unnecessary re-runs.

## Analysis

### Why No Violations Were Found

The `advanced-event-handler-refs` and `advanced-use-latest` rules address a specific pattern:

```tsx
// PROBLEMATIC: Hook accepts callback prop, uses in effect
function useWindowEvent(event: string, handler: (e) => void) {
  useEffect(() => {
    window.addEventListener(event, handler);
    return () => window.removeEventListener(event, handler);
  }, [event, handler]); // Re-subscribes whenever handler changes
}
```

This codebase avoids this pattern in several ways:

1. **Stable State Setters**: All event listeners use `useState` setters (e.g., `setIsOnline`, `setIsOpen`), which are guaranteed stable by React.

2. **No Callback Prop Subscriptions**: Hooks that accept callback props (like `useControllableState`) use them in returned functions, not inside `useEffect` subscriptions.

3. **Component Props vs. addEventListener**: Components like `MediaPlayer` and dnd-kit pass callbacks to component props, not raw `addEventListener` calls. React handles the lifecycle.

4. **useSyncExternalStore**: For localStorage synchronization, the codebase uses React's `useSyncExternalStore`, which properly manages subscription lifecycle.

### Pattern Quality

The codebase demonstrates good patterns:

- **Functional setState**: Used consistently (e.g., `setIsOpen((prev) => !prev)`)
- **Stable callbacks**: `useCallback` with correct dependencies
- **Empty deps for static handlers**: Event handlers that only use stable refs have `[]` deps

## Recommendations

No changes required. The codebase already follows best practices for event handler management.

### If Future Hooks Need Callback Props

If a future hook needs to accept a callback prop for use in an event listener, implement either:

**Option A: Ref Pattern**

```tsx
function useWindowEvent(event: string, handler: (e: Event) => void) {
  const handlerRef = useRef(handler);
  useEffect(() => {
    handlerRef.current = handler;
  }, [handler]);

  useEffect(() => {
    const listener = (e: Event) => handlerRef.current(e);
    window.addEventListener(event, listener);
    return () => window.removeEventListener(event, listener);
  }, [event]);
}
```

**Option B: useEffectEvent (React 19+)**

```tsx
import { useEffectEvent } from "react";

function useWindowEvent(event: string, handler: (e: Event) => void) {
  const onEvent = useEffectEvent(handler);

  useEffect(() => {
    window.addEventListener(event, onEvent);
    return () => window.removeEventListener(event, onEvent);
  }, [event]);
}
```
