## Findings

### 1. rendering-animate-svg-wrapper (LOW)

**Status:** ⚠️ Multiple instances of SVG animations found

**Finding:** The codebase uses Lucide's `Loader2` component with `animate-spin` class directly on the SVG element. This applies CSS animation directly to the SVG, which may not benefit from GPU acceleration.

**Files affected:** 38 instances across the codebase

| File                                           | Line | Pattern                                       |
| ---------------------------------------------- | ---- | --------------------------------------------- |
| `components/items/items-view.tsx`              | 602  | `<Loader2 className="size-4 animate-spin" />` |
| `components/items/items-view.tsx`              | 625  | `<Loader2 className="size-4 animate-spin" />` |
| `components/search/spotlight-search.tsx`       | 206  | `<Loader2 className="... animate-spin" />`    |
| `components/google-drive/sync-history.tsx`     | 112  | `<Loader2 className="... animate-spin" />`    |
| `components/google-drive/sync-history.tsx`     | 149  | `<Loader2 className="... animate-spin" />`    |
| `components/items/fork-destination-dialog.tsx` | 197  | `<Loader2 className="... animate-spin" />`    |
| `components/items/fork-destination-dialog.tsx` | 207  | `<Loader2 className="... animate-spin" />`    |
| `components/items/fork-destination-dialog.tsx` | 312  | `<Loader2 className="... animate-spin" />`    |
| ... and 30+ more instances                     |      |                                               |

**Recommendation:** Create a `<Spinner />` wrapper component that wraps the SVG in a div:

```tsx
// components/ui/spinner.tsx
export function Spinner({ className }: { className?: string }) {
  return (
    <div className={cn("animate-spin", className)}>
      <Loader2 className="size-full" />
    </div>
  );
}
```

**Decision:** DEFERRED to future work. The current implementation works correctly; this is a low-impact micro-optimization. Lucide icons are small and simple, so the performance benefit is minimal.

### 2. rendering-content-visibility (HIGH)

**Status:** ⚠️ Opportunities for improvement

**Finding:** Several components render lists that could benefit from `content-visibility: auto` to skip off-screen rendering.

| File                                           | List Type             | Virtualized? | Notes                                |
| ---------------------------------------------- | --------------------- | ------------ | ------------------------------------ |
| `components/items/fork-destination-dialog.tsx` | Folder list           | ✅ Yes       | Uses `@tanstack/react-virtual`       |
| `components/search/spotlight-search.tsx`       | Search results        | ❌ No        | Could have many items                |
| `components/google-drive/sync-history.tsx`     | Sync log entries      | ❌ No        | Typically < 50 items, limited by API |
| `components/sortable-tree/Tree.tsx`            | Tree items            | ❌ No        | Flattened tree could have many items |
| `components/sortable-grid/Grid.tsx`            | Grid items            | ❌ No        | Could have many items                |
| `components/items/image-selection-grid.tsx`    | TMDB images           | ❌ No        | Limited by `initialLimit` prop (8)   |
| `components/items/items-view.tsx`              | Items (via Tree/Grid) | ❌ No        | Delegates to Tree/Grid components    |

**Recommendation:** Add `content-visibility: auto` CSS to list items as a lightweight optimization, OR implement virtualization for lists that could exceed 50 items.

**Files to potentially add content-visibility:**

1. Tree/SortableTree - for `<li>` elements
2. Grid/SortableGrid - for grid items
3. CommandItem in spotlight-search - for search results

**Decision:** DEFERRED to future work. The current implementation handles lists well with pagination (image-selection-grid) and limited counts (sync-history). Virtualization is already in place for fork-destination-dialog. Full virtualization for Tree/Grid views would be a significant architectural change.

### 7. rendering-conditional-render (LOW)

**Status:** ⚠️ One potential issue found

**Finding:** Most conditional rendering is done safely with boolean checks. One potentially unsafe pattern found:

**File:** `components/sortable-tree/components/TreeItem/TreeItem.tsx:266`

```tsx
{clone && childCount && childCount > 1 && (
  <span ...>{childCount}</span>
)}
```

If `childCount` is `0`, this would render `0` in the DOM because `true && 0` evaluates to `0`.

**Analysis:** In practice, `childCount` is always `>= 1` when `clone` is true (it's calculated as `getChildCount(items, activeId) + 1`), so this is not a runtime issue. However, the pattern is technically unsafe.

**Recommendation:** Use explicit ternary or comparison:

```tsx
{clone && childCount && childCount > 1 ? (
  <span ...>{childCount}</span>
) : null}
```

**Other safe patterns found:**

- `progressPercentage !== null && ...` ✅ Correct null check
- `description && ...` ✅ Safe (string falsy = empty)
- `shouldShowWatched && ...` ✅ Safe (boolean)
- `items.length > 0 && ...` ✅ Safe (boolean comparison)
