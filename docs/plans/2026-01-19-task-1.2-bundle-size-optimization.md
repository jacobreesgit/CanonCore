# Task 1.2: Bundle Size Optimization - Audit Findings

**Date**: 2026-01-19
**Status**: Completed
**Rules Applied**: bundle-barrel-imports, bundle-dynamic-imports, bundle-defer-third-party, bundle-conditional, bundle-preload

## Summary

Audited 19 files for bundle optimization opportunities. Implemented 2 fixes that provide immediate bundle size improvements with minimal refactoring risk.

## Changes Made

### 1. Added `optimizePackageImports` to next.config.mjs (CRITICAL)

**File**: `next.config.mjs`
**Rule**: bundle-barrel-imports

**Problem**: 68 files import from `lucide-react` barrel file (`from "lucide-react"`), and 2 files import from `date-fns` barrel file. Barrel imports can significantly increase bundle size because bundlers may not tree-shake them effectively.

**Solution**: Added `optimizePackageImports` to Next.js config:

```js
experimental: {
  optimizePackageImports: ["lucide-react", "date-fns"],
},
```

**Impact**: Next.js now automatically tree-shakes these barrel imports, reducing the initial bundle size. Confirmed working in build output:

```
- Experiments (use with caution):
  · optimizePackageImports
```

### 2. Deferred Vercel Analytics Loading (MEDIUM)

**Files**: `app/layout.tsx`, `components/deferred-analytics.tsx` (new)
**Rule**: bundle-defer-third-party

**Problem**: `@vercel/analytics/next` was imported synchronously in the root layout, adding to the initial bundle.

**Solution**: Created a deferred wrapper component that uses `next/dynamic` with `ssr: false` to load analytics after hydration:

```tsx
const Analytics = dynamic(
  () => import("@vercel/analytics/next").then((mod) => mod.Analytics),
  { ssr: false }
);
```

**Impact**: Analytics code is now loaded after the critical rendering path, improving initial page load performance.

## Findings Not Implemented (Future Work)

The following optimization opportunities were identified but NOT implemented due to complexity, testing risk, or marginal benefit. These have been added to the future work document.

### 1. Dynamic Import of Heavy Components

**Rule**: bundle-dynamic-imports

Several heavy components could be dynamically imported:

| Component         | Location                                    | Dependency                | Reason Not Implemented                                                                           |
| ----------------- | ------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------ |
| `VideoPlayer`     | `components/media/media-player.tsx`         | `@vidstack/react` (~50KB) | Used conditionally but requires refactoring MediaOverlay; CSS imports complicate dynamic loading |
| `SortableTree`    | `components/sortable-tree/SortableTree.tsx` | `@dnd-kit/core` (~15KB)   | Only used in edit mode, but deeply integrated with items-view.tsx                                |
| `SortableGrid`    | `components/sortable-grid/SortableGrid.tsx` | `@dnd-kit/core` (~15KB)   | Same as SortableTree                                                                             |
| `SpotlightSearch` | `components/search/spotlight-search.tsx`    | `cmdk`                    | Already lazy-loaded via modal pattern                                                            |
| `ItemHero`        | `components/items/item-hero.tsx`            | `motion/react`            | Core UI component, always visible                                                                |

**Recommendation**: Consider dynamic importing `SortableTree`/`SortableGrid` in a future sprint when edit mode is entered, as dnd-kit is only needed when reordering.

### 2. Shader1 Component

**File**: `components/shader1.tsx` (referenced by `item-hero.tsx`, `media-player.tsx`)

The WebGL shader component is already conditionally skipped in automated test environments (`navigator.webdriver`), but could benefit from:

- Lazy loading when no artwork is available
- Intersection Observer to only load when visible

**Recommendation**: Low priority - shader is only loaded as a fallback.

### 3. Preload on Hover/Focus

**Rule**: bundle-preload

Potential opportunities:

- "Edit" button could preload `@dnd-kit/core` on hover
- "Play" button could preload `@vidstack/react` on hover

**Recommendation**: Micro-optimization with complex implementation. Lower priority than other improvements.
