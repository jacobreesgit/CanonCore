## Performance Rules Audited

1. **Virtualize large lists (>50 items)** - not for grid or tree
2. **No layout reads in render** (`getBoundingClientRect`, `offsetHeight`, `offsetWidth`, `scrollTop`)
3. **Batch DOM reads/writes** - avoid interleaving
4. **Prefer uncontrolled inputs** - controlled inputs must be cheap per keystroke
5. **Add `<link rel="preconnect">` for CDN/asset domains**
6. **Critical fonts: `<link rel="preload" as="font">` with `font-display: swap`**

### 5. Preconnect for CDNs (Rule 5)

**External domains used by the application:**

| Domain                  | Purpose                     | Client-side?        |
| ----------------------- | --------------------------- | ------------------- |
| `image.tmdb.org`        | TMDB poster/backdrop images | ✅ Yes              |
| `api.themoviedb.org`    | TMDB API                    | ❌ Server-side only |
| `oauth2.googleapis.com` | Google OAuth                | ❌ Server-side only |
| `www.googleapis.com`    | Google Drive API            | ❌ Server-side only |

**Issue Found:** `image.tmdb.org` is used client-side for poster thumbnails in `media-search-combobox.tsx` and `image-selection-grid.tsx` but had no preconnect link.

**Fix Applied:** Added preconnect to `app/layout.tsx`:

```tsx
<head>
  {/* Preconnect to TMDB image CDN for faster poster/backdrop loading */}
  <link rel="preconnect" href="https://image.tmdb.org" />
</head>
```

### 6. Font Preloading (Rule 6)

**Finding:** The application uses `next/font/google` for Geist and Geist Mono fonts (app/layout.tsx:14-21). This Next.js feature automatically:

- Self-hosts fonts to eliminate external requests
- Adds `font-display: swap` by default
- Preloads fonts during build

**Result:** ✅ Compliant via Next.js built-in optimization.
