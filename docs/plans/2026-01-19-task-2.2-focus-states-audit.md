# Task 2.2: Focus States Audit

**Date:** 2026-01-19
**Auditor:** Claude Code (Opus 4.5)
**Status:** Complete

## Rules Applied

1. **Interactive elements need visible focus states** - `focus-visible:ring-*` or equivalent
2. **Never remove outline without focus replacement** - No `outline-none` without alternative
3. **Use `:focus-visible` over `:focus`** - Avoid focus ring on click
4. **Group focus with `:focus-within`** - For compound controls

## Executive Summary

The codebase demonstrates **good overall focus state hygiene**. The global CSS sets a base `outline-ring/50` on all elements, and most interactive components use proper `focus-visible:ring-*` patterns. The primary issues found relate to **Rule 3** - several shadcn/ui components and custom components use `focus:` instead of `focus-visible:`, which shows focus rings on mouse clicks rather than only on keyboard navigation.

**Key Decision:** Many shadcn/ui components (context-menu, dropdown-menu, select items) use `focus:` intentionally because Radix UI libraries programmatically focus these elements during keyboard navigation. Changing these to `focus-visible:` would break keyboard navigation feedback. These are **intentional patterns** and should not be modified.
