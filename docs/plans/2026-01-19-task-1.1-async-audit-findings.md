# Async Patterns Audit Findings - Task 1.1

This document contains the findings from the "Eliminating Waterfalls" audit as part of the comprehensive codebase audit plan.

## Summary

Audited files against 5 async rules:

- `async-defer-await` - Move await into branches where actually used
- `async-parallel` - Use Promise.all() for independent operations
- `async-dependencies` - Use better-all for partial dependencies
- `async-api-routes` - Start promises early, await late in API routes
- `async-suspense-boundaries` - Use Suspense to stream content

**Total Issues Found:** 15 actionable items across 12 files

### 🔍 Issues Found

#### 1. `app/api/artwork/[fileId]/route.ts`

**Rule:** `async-api-routes`
**Issue:** Sequential `auth()` → `params` → `prisma` query
**Location:** Lines 19-30
**Fix:** Start all promises early, await late

```typescript
// Before
const session = await auth();
const { fileId } = await params;
const file = await prisma.itemFile.findUnique(...);

// After
const [session, { fileId }] = await Promise.all([auth(), params]);
const file = await prisma.itemFile.findUnique(...);
```

#### 2. `app/api/stream/[fileId]/route.ts`

**Rule:** `async-api-routes`
**Issue:** Same pattern as artwork route
**Location:** Lines 20-35
**Fix:** Same as above - parallel auth and params

#### 3. `app/api/username/check/route.ts`

**Rule:** `async-defer-await`
**Issue:** `auth()` awaited at line 34 but only used conditionally at line 79
**Location:** Lines 34, 79
**Fix:** Move await into the branch where it's actually used

```typescript
// Before (line 34)
const session = await auth();
// ... validation ...
// (line 79) if (session?.user?.id) {...}

// After - defer await to usage point
const sessionPromise = auth();
// ... validation ...
const session = await sessionPromise;
if (session?.user?.id) {...}
```

#### 4. `app/api/auth/callback/google-drive/route.ts`

**Rule:** `async-parallel`
**Issue:** `getUserEmail()` and `createRootFolder()` called sequentially
**Location:** Lines 80, 87
**Fix:** Run in parallel with Promise.all

```typescript
// Before
const email = await getUserEmail(tokens.access_token!);
const rootFolderId = await createRootFolder(tokens);

// After
const [email, rootFolderId] = await Promise.all([
  getUserEmail(tokens.access_token!),
  createRootFolder(tokens),
]);
```

### 🔍 Issues Found

#### 5. `lib/auth-actions.ts` - `signUp()`

**Rule:** `async-parallel`
**Issue:** Sequential username and email uniqueness checks
**Location:** Lines 70-90 (approx)
**Fix:** Run uniqueness checks in parallel

```typescript
// Before
const existingUsername = await prisma.user.findFirst({...});
const existingEmail = await prisma.user.findUnique({...});

// After
const [existingUsername, existingEmail] = await Promise.all([
  prisma.user.findFirst({...}),
  prisma.user.findUnique({...}),
]);
```

#### 6. `lib/item-actions.ts` - Multiple functions

**Rule:** `async-parallel`
**Issue:** Sequential `checkRateLimit()` + `auth()` pattern repeated
**Affected Functions:** `createItem`, `updateItem`, `deleteItem`, `reorderItems`, `pinItem`, `unpinItem`
**Fix:** Run rate limit and auth in parallel

```typescript
// Before
const rateLimitResult = await checkRateLimit("itemCreate");
const session = await auth();

// After
const [rateLimitResult, session] = await Promise.all([
  checkRateLimit("itemCreate"),
  auth(),
]);
```

#### 7. `lib/fork-actions.ts` - `forkItem()`

**Rule:** `async-parallel`
**Issue:** Multiple sequential queries that could be parallel
**Location:** Lines 50-80 (approx)
**Fix:** Run independent queries in parallel

```typescript
// Before
const sourceItem = await prisma.item.findUnique({...});
const existingFork = await prisma.fork.findUnique({...});
const publicCheck = await isItemFullyPublic(sourceItemId);

// After
const [sourceItem, existingFork, publicCheck] = await Promise.all([
  prisma.item.findUnique({...}),
  prisma.fork.findUnique({...}),
  isItemFullyPublic(sourceItemId),
]);
```

#### 8. `lib/user-actions.ts` - `changePassword()`

**Fix:** Run in parallel

#### 9. `lib/tmdb-actions.ts` - `applyMetadataAction()`

**Rule:** `async-parallel`
**Issue:** `downloadPoster()` and `downloadBackdrop()` run sequentially
**Location:** Inside applyMetadataAction
**Fix:** Run downloads in parallel

// After

#### 10. `lib/google-drive-actions.ts` - `moveItemInGoogleDrive()`

## Rules Quick Reference

| Rule                        | When to Apply                                                      |
| --------------------------- | ------------------------------------------------------------------ |
| `async-defer-await`         | When await is at function start but value used later/conditionally |
| `async-parallel`            | When multiple awaits are independent (no data dependency)          |
| `async-dependencies`        | When some operations depend on partial results of others           |
| `async-api-routes`          | In route handlers - start promises early, await late               |
| `async-suspense-boundaries` | When page can show shell/skeleton while data loads                 |
