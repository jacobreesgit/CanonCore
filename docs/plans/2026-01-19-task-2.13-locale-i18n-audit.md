# Task 2.13: Locale & i18n Audit

**Status:** Completed
**Date:** 2026-01-19

## Overview

This task audited the codebase for locale and internationalization (i18n) compliance, focusing on three rules:

1. Use `Intl.DateTimeFormat` for date formatting
2. Use `Intl.NumberFormat` for number formatting
3. Detect language via headers/navigator, not IP

## Files Audited

- `lib/progress-utils.ts` - Progress label formatting
- `components/items/item-stats.tsx` - Item count display
- `components/google-drive/storage-bar.tsx` - Storage quota display
- `components/google-drive/sync-history.tsx` - Duration formatting
- `components/google-drive/settings-section.tsx` - Date distance formatting
- `lib/upload-utils.ts` - File size formatting
- `components/ui/dropzone.tsx` - File list and size formatting

## Findings

### Rule 1: Intl.DateTimeFormat ✅

**Finding:** The codebase uses `date-fns` library's `formatDistanceToNow()` for relative time formatting.

**Locations:**

- `components/google-drive/sync-history.tsx:210`
- `components/google-drive/settings-section.tsx:182`

**Assessment:** Acceptable. date-fns is a widely-used library that supports localization through locale imports. The current implementation uses English defaults but could be extended with locale support.

### Rule 2: Intl.NumberFormat ⚠️ → ✅ Fixed

**Finding:** Multiple functions used hardcoded `.toFixed()` for number formatting.

**Issues Found:**

1. **`components/google-drive/storage-bar.tsx:29-40`** - `formatBytes()` used `.toFixed(1)` and `.toFixed(0)`
2. **`lib/upload-utils.ts:385-398`** - `formatBytes()` used `.toFixed(1)` and `Math.round()`
3. **`components/ui/dropzone.tsx:27-40`** - `renderBytes()` used `.toFixed(2)`
4. **`components/google-drive/sync-history.tsx:61-65`** - `formatDuration()` used `.toFixed(1)`

**Fixes Applied:**

All formatting functions now use cached `Intl.NumberFormat` instances:

```typescript
// Example from storage-bar.tsx
const numberFormatter = new Intl.NumberFormat(undefined, {
  maximumFractionDigits: 1,
});

const wholeNumberFormatter = new Intl.NumberFormat(undefined, {
  maximumFractionDigits: 0,
});
```

Using `undefined` as the locale automatically uses the runtime's default locale (e.g., `navigator.language` in browsers).

### Rule 3: Language Detection ⚠️ → ✅ Fixed

**Finding:** `components/ui/dropzone.tsx` hardcoded the English locale.

**Issue Found:**

```typescript
// Before - hardcoded "en" locale
new Intl.ListFormat("en");
```

**Fix Applied:**

```typescript
// After - uses runtime default locale
new Intl.ListFormat(undefined, { type: "conjunction" });
```

1. **Locale-Aware Numbers:** Numbers now display with appropriate thousand separators (e.g., "1,024 GB" in en-US)
2. **Correct Decimal Formatting:** Decimal points use locale-appropriate separators
3. **List Formatting:** File lists use locale-appropriate conjunctions ("and" in English, "und" in German, etc.)
4. **Future-Proof:** Adding full i18n support is now easier since formatting already respects locale
