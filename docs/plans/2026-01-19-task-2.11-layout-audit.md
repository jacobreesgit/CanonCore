# Task 2.11: Safe Areas & Layout Audit

**Date**: 2026-01-19
**Status**: In Progress
**Category**: Web Design Guidelines - Layout

## Rules Audited

1. **Full-bleed layouts use `env(safe-area-inset-*)`** - Accommodate device notches and safe zones
2. **Avoid unwanted scrollbars** - `overflow-x-hidden` on containers, fix content overflow
3. **Prefer Flex/Grid over JS measurement** - CSS-based layouts preferred to JS dimension calculations

## Files Audited

- `app/globals.css`
- `app/layout.tsx`
- `app/(my-items)/layout.tsx`
- `app/(public)/layout.tsx`
- `app/(auth)/sign-in/page.tsx` (full-bleed example)
- `components/app-sidebar.tsx`
- `components/ui/sidebar.tsx`
- `components/items/items-view.tsx`
- Additional files via grep search for overflow, safe-area, and JS measurements

---

## Findings

### Issue 1: Missing viewport-fit=cover (HIGH)

**Location**: `app/layout.tsx`
**Rule**: Full-bleed layouts require proper viewport configuration for safe area insets to work

**Finding**: The app doesn't have `viewportFit: 'cover'` in the metadata configuration. This is required for `env(safe-area-inset-*)` CSS to work on devices with notches (iPhone X+, etc.).

**Current Code**:

```tsx
export const metadata: Metadata = {
  title: "CanonCore",
  description: "CanonCore - Media Library Manager",
  // No viewport configuration
};
```

**Fix**: Add viewport configuration with `viewportFit: 'cover'`

---

### Issue 2: Missing safe-area-inset CSS (HIGH)

**Location**: `app/globals.css`
**Rule**: Full-bleed layouts require `env(safe-area-inset-*)` to accommodate device notches

**Finding**: No safe-area-inset CSS utilities exist in the codebase. Full-bleed layouts like:

- Auth pages: `h-screen overflow-hidden` with absolute positioned backgrounds
- Main layouts: `h-svh overflow-hidden` with sidebar navigation

These need padding that respects device safe areas for proper display on notched devices.

**Fix**: Add CSS custom properties or utilities for safe-area-inset values

The app uses `overflow-hidden` appropriately to prevent unwanted scrollbars:

- `app/layout.tsx:56` - Body has `overflow-hidden` to prevent document-level scrollbars
- `app/(my-items)/layout.tsx:47` - SidebarProvider has `h-svh overflow-hidden`
- `app/(public)/layout.tsx:27` - SidebarProvider has `h-svh overflow-hidden`

### 3. CSS-Based Layouts ✓

All layout positioning uses Flex/Grid instead of JS measurements:

- Sidebar uses CSS Flex for layout (`components/ui/sidebar.tsx`)
- Items view uses CSS Flex (`components/items/items-view.tsx`)
- All layouts use Tailwind CSS utilities for positioning

## Implementation Plan

### Fix 1: Add viewport-fit=cover

Add viewport configuration to `app/layout.tsx`:

```tsx
export const viewport: Viewport = {
  viewportFit: "cover",
};
```

### Fix 2: Add safe-area-inset CSS

Add CSS custom properties to `app/globals.css`:

```css
:root {
  /* Safe area insets for notched devices */
  --safe-area-inset-top: env(safe-area-inset-top, 0px);
  --safe-area-inset-right: env(safe-area-inset-right, 0px);
  --safe-area-inset-bottom: env(safe-area-inset-bottom, 0px);
  --safe-area-inset-left: env(safe-area-inset-left, 0px);
}
```

### Fix 3: Apply safe-area padding to layouts

Update layouts to use safe-area padding where needed:

- Auth pages: Add `padding-top: var(--safe-area-inset-top)` etc.
- Main content areas that go edge-to-edge
